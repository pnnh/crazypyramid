# Feature Specification: First-Person Visuals (第一人称手臂 + 方块贴图集)

**Feature Branch**: `002-first-person-visuals`

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "在001体素世界MVP闭环完成之后，提升视觉表现：(1) 让玩家能看到自己的第一人称手臂，而不是只有一个悬浮摄像机；(2) 用像素风格贴图集替换当前纯色方块，至少覆盖草方块顶部、草方块侧面、泥土、石头这几种类型，网格生成改为按面采样贴图集而不是读顶点色。不改变001已确定的挖掘/放置/移动/跳跃等核心玩法，不包含第三人称角色、不包含体素光照传播系统。"

### User Story 1 - 看到更真实的方块材质 (Priority: P1)

玩家在世界中看到的方块不再是单一纯色色块，而是带有草地、泥土、石头质感的贴图，草方块的顶部和侧面在视觉上也能区分开（符合"顶部是草、往下是土"的直觉）。

**Why this priority**: 这是当前视觉效果里最明显的"看起来不真实"的来源，几乎每一刻游玩都会看到方块，视觉收益覆盖面最大；相比之下第一人称手臂只在特定视角下才被注意到。

**Independent Test**: 在已有的 001 世界里直接观察方块外观（不需要手臂功能已完成），确认草顶/草侧/泥土/石头四者贴图在视觉上彼此可区分，且与之前纯色版本相比明显更接近"真实材质"的观感。

**Acceptance Scenarios**:

1. **Given** 世界已生成，**When** 玩家看向一块草方块的顶面，**Then** 看到的是带有草地纹理的贴图，而不是单一纯色色块。
2. **Given** 世界已生成，**When** 玩家看向同一块草方块的侧面，**Then** 看到的贴图与顶面贴图不同（按侧面专用贴图呈现），且能看出这是"草方块的侧面"而不是另一种方块。
3. **Given** 玩家通过挖掘看到了泥土或石头方块（例如山丘内部），**When** 玩家观察这些方块，**Then** 泥土呈现泥土质感贴图、石头呈现石头质感贴图，二者及与草方块都能明显区分。
4. **Given** 玩家挖掉一个方块或放置一个新方块（沿用 001 的挖掘/放置操作），**When** 操作完成，**Then** 受影响位置的方块渲染同样正确使用对应类型的贴图，不会出现贴图丢失、花屏，或退回成纯色块的情况。

---

### User Story 2 - 看到自己的第一人称手臂 (Priority: P2)

玩家在游玩过程中能看到一个挂在自己视角下的手臂模型，而不是感觉自己只是一台悬浮在空中的摄像机。

**Why this priority**: 提升沉浸感，但不影响玩家对核心玩法（能挖、能建）的理解——001 的验收标准在没有手臂的情况下已经成立。属于锦上添花，独立于贴图工作，可以排在其后。

**Independent Test**: 在已有的 001 世界里（不需要贴图集已完成）观察第一人称视角，确认能看到一个随视角移动的手臂模型，并确认其不会干扰挖掘/放置的瞄准判定。

**Acceptance Scenarios**:

1. **Given** 玩家已进入游戏并被摄像机控制，**When** 玩家观察自己的视角画面，**Then** 能看到一个第一人称手臂模型稳定出现在画面中（而不是完全空无一物）。
2. **Given** 玩家转动视角或移动，**When** 画面随之变化，**Then** 手臂模型跟随视角自然移动，不出现明显穿模、抖动或脱节漂移。
3. **Given** 手臂模型已经显示，**When** 玩家执行挖掘或放置操作（瞄准方块、左键/右键），**Then** 瞄准判定仍然准确命中玩家实际看向的方块，不会被手臂模型自身误挡/误命中。

---

### Edge Cases

- 玩家瞄准方块时，手臂模型本身不能被挖掘/放置的射线检测误识别为"瞄准到的方块"（手臂不是世界中的可挖掘物体）。
- 贴图集中某个方块类型的贴图缺失或加载失败时，该方块的渲染不应导致整个材质报错变黑/变紫（引擎默认的"缺失贴图"占位效果可以接受，不要求额外的容错设计）。
- 方块的六个面中，石头和泥土预期各面使用同一张贴图（无方向区分）；只有草方块需要区分"顶面贴图"与"侧面贴图"——侧面贴图本身覆盖该方块侧面的完整外观（具体是否带有顶部草色过渡见下方 Clarifications）。
- 基岩（世界最底层、不可挖除的方块类型）本次不强制要求专属贴图，可沿用简单的深色贴图或纯色，因为玩家正常游玩很少会看到它。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须为草方块顶部、草方块侧面、泥土方块、石头方块这几种可见方块类型分别提供独立的像素风格贴图素材。草方块侧面贴图是整个侧面统一的草色质感（不做顶部草色到底部泥土色的过渡渐变）。
- **FR-002**: 系统必须将这些贴图整合进一个贴图集（texture atlas）资源中，供体素方块材质统一采样，而不是为每种方块类型使用单独的材质/贴图资源。
- **FR-003**: 方块网格生成逻辑必须为每个可见面分配正确的UV坐标，使其采样到贴图集中与该方块类型（以及朝向，特别是草方块的顶/侧区分）相匹配的子区域。
- **FR-004**: 挖掘或放置方块后，受影响的新增/剩余方块渲染必须和世界初始生成时一样正确使用贴图集，不出现"初始生成正确、编辑后失效"的不一致。
- **FR-005**: 玩家在游玩时必须能看到一个挂载在第一人称视角下的手臂模型（完全空手，不包含任何手持工具/物品模型），替代当前完全看不到自身的状态。
- **FR-006**: 手臂模型必须只在第一人称视角中可见渲染，并且不能参与或干扰挖掘/放置操作的瞄准射线检测。
- **FR-007**: 手臂模型必须随摄像机视角变化保持视觉上稳定、合理的跟随，不出现穿模、漂移或脱节。
- **FR-008**: 本次视觉替换不得改变 001 feature 已确定的挖掘、放置、移动、跳跃等核心玩法行为——这次改动的范围仅限外观表现，不引入新的游戏机制。

### Key Entities *(include if feature involves data)*

- **Block Texture Atlas（方块贴图集）**: 一张整合了各方块类型（及草方块顶/侧区分）贴图子区域的图集资源，供体素材质统一采样。
- **Block Face UV Mapping（方块面UV映射）**: 方块类型与朝向（顶/侧/底）到贴图集中具体子区域坐标的对应关系，供网格生成逻辑在构建每个面时使用。
- **First-Person Arm Model（第一人称手臂模型）**: 挂载在第一人称摄像机下、随视角移动的可见模型资源。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家进入游戏后，无需任何额外说明，仅凭观察就能分辨出草地顶部、草地侧面、泥土、石头这几类方块在材质外观上的不同，而不是看到大片相同的纯色色块。
- **SC-002**: 一名此前没有看过本项目代码或美术资源的人游玩后，会认为这些方块"看起来像真实的草地/泥土/石头"，而不是明显的程序占位色块——这是对 001 feature 中 SC-006（"看起来像一个可挖掘和建造的方块世界"）的视觉层面加强。
- **SC-003**: 玩家进入游戏后，能在自己的视角画面中看到属于自己的第一人称手臂模型，而不是感觉"自己只是一台悬浮摄像机"。
- **SC-004**: 连续执行至少 20 次挖掘/放置混合操作后，所有新增或剩余方块的贴图渲染始终保持正确，不出现贴图丢失、闪烁或花屏（延续 001 feature 中 SC-005 的验证规模基准，只是这次额外检查贴图而不是颜色）。
- **SC-005**: 引入手臂模型后，瞄准/挖掘/放置的判定准确率与 001 feature 验收时保持一致——手臂模型不会导致玩家明显感觉"瞄不准"或"误触发"的情况增多。

## Assumptions

- 贴图风格统一采用与现有程序化方块相匹配的像素风格（低分辨率、块状）美术基调，具体像素分辨率规格（例如每张贴图的像素尺寸）在 `/speckit-plan` 阶段结合 Pixellab 的生成能力确定，不在本规格中锁定具体数值。
- 石头、泥土方块的六个面默认使用同一张贴图（不区分朝向）；只有草方块需要区分顶面与侧面贴图，这是目前唯一需要按朝向区分贴图的方块类型。
- 基岩方块本次不要求专属贴图素材，可以沿用一张简单的深色基础贴图或继续使用纯色，因为玩家在正常游玩节奏下很少会直接看到基岩层。
- 手臂模型不需要骨骼绑定的复杂动画；固定姿势、或仅有呼吸/轻微摆动这类简单程度的动作表现即可满足本次范围，不要求挖掘/放置时有对应的挥动动画。
- 手臂模型为静态或极简动画的美术资源，通过本地已连接的 Blender MCP 生成，再导入 Unreal；具体的文件格式/导入流程细节留给 `/speckit-plan` 阶段决定。
- 贴图集中各方块类型贴图通过本地已连接的 Pixellab MCP （更适合像素风格2D贴图生成的工具）手动生成固定数量的几张贴图，不要求支持运行时美术内容热更新或供非开发者使用的美术工具链工作流。
- 本次视觉替换完全不改变 001 feature 已确定的挖掘/放置/移动/跳跃等核心玩法逻辑，只替换方块渲染方式（贴图集代替顶点色）和新增手臂模型的展示，不涉及新游戏机制。
