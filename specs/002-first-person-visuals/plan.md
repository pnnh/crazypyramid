# Implementation Plan: First-Person Visuals (第一人称手臂 + 方块贴图集)

**Branch**: `002-first-person-visuals` | **Date**: 2026-10-20 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-first-person-visuals/spec.md`

## Summary

Replace 001's placeholder visuals with two independent, additive changes: (1) a texture atlas
(Grass Top, Grass Side, Dirt, Stone, **and Bedrock** — five cells, one uniform path, no
vertex-color special-case) sampled via real per-face UVs in the existing chunk mesh builder, and
(2) a bare-handed first-person arm static mesh attached under the camera with a simple
code-driven idle sway (no skeleton/animation). Art is generated by Pixellab MCP (textures) and
Blender MCP (arm mesh) per the Constitution's tool-assisted workflow; all core logic (UV lookup,
mesh generation, arm sway) stays hand-written C++. Neither change alters 001's gameplay logic
(FR-008) — `AddIgnoredActor(this)` in the existing aim trace already covers the new arm mesh
for free, since it's a component of the same character actor.

## Technical Context

**Language/Version**: C++ (same UnrealBuildTool/Engine 5.8 toolchain as 001). No new Blueprint logic required.

**Primary Dependencies**: Existing `ProceduralMeshComponent`/`Engine` modules (now also emitting real UVs); `unreal-mcp` `TextureTools`/`MaterialTools`/`AssetTools` for importing the atlas texture and arm mesh and wiring the material graph; Pixellab MCP (one-time texture generation, not a runtime dependency); Blender MCP (one-time arm mesh generation/export, not a runtime dependency).

**Storage**: N/A — no new persisted state; the atlas texture and arm mesh are static content assets, not runtime data.

**Testing**: Manual PIE validation per `quickstart.md` (Constitution Development Workflow — no automated test suite at this project phase).

**Target Platform**: Unreal Editor PIE on Desktop — unchanged from 001.

**Project Type**: Same single Unreal project, extending the existing `MyProject` module in place.

**Performance Goals**: No quantitative target. Qualitative: adding UV computation to the existing per-face meshing loop and a trivial per-frame sway transform must not introduce any perceptible stutter beyond 001's already-established async-remesh baseline.

**Constraints**: Must not change 001's gameplay behavior (spec FR-008). The arm mesh must never be hittable by the break/place aim trace (spec FR-006) — already satisfied structurally by the existing `FCollisionQueryParams::AddIgnoredActor(this)` call in `AVoxelCharacter::TraceForTargetVoxel`, since the arm mesh will be a component of that same actor; no new ignore logic needs to be written. Pixel-art textures must stay crisp at typical play distance (no mip/bilinear atlas-edge bleeding).

**Scale/Scope**: One 5-cell texture atlas (Grass Top, Grass Side, Dirt, Stone, Bedrock); one static-mesh first-person arm; no skeletal animation, no new input actions, no new gameplay systems.

### Source Code (repository root)

Extends the existing `Source/MyProject` module and `001`'s Voxel/Player code in place — no new
module, no new top-level directories.

```text
Source/MyProject/
├── Public/Voxel/
│   ├── VoxelTypes.h           # extend VoxelBlockRules with atlas-cell lookup per (type, face)
│   └── VoxelMeshBuilder.h     # FVoxelChunkMeshInput/FVoxelMeshData unchanged in shape; UVs now real
├── Private/Voxel/
│   ├── VoxelTypes.cpp         # implement atlas-cell lookup table
│   └── VoxelMeshBuilder.cpp   # compute real per-corner UVs instead of (0,0)
├── Public/Player/
│   └── VoxelCharacter.h       # add arm StaticMeshComponent member + Tick override for idle sway
└── Private/Player/
    └── VoxelCharacter.cpp     # create/attach arm component in constructor; sway logic in Tick

Content/VoxelSandbox/
├── Textures/T_BlockAtlas       # new: imported atlas texture (5 cells, Nearest filter, no mips)
├── Meshes/SM_FirstPersonArm    # new: imported static mesh (from Blender MCP export)
├── Materials/
│   ├── M_VoxelChunk            # modified: VertexColor path replaced with atlas TextureSample
│   └── M_FirstPersonArm        # new: simple lit material for the arm mesh
```

**Structure Decision**: No new module/project boundary. The arm is a plain `UStaticMeshComponent`
member added directly to the existing `AVoxelCharacter` (not a new Actor/Component class) —
it's a single cohesive piece of state alongside the existing `FirstPersonCamera` member,
consistent with that existing pattern; a dedicated component class would be unjustified
abstraction for one static mesh and a sine-wave sway (Constitution Principle III).
