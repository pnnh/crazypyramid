# Feature Specification: Voxel World MVP (体素世界核心闭环)

**Feature Branch**: `001-voxel-world-mvp`

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "体素世界核心闭环 MVP — 玩家在一个由区块(chunk)组成、带噪声起伏地形、分层多种方块类型的小世界中第一人称行走观察，可以左键挖除瞄准的方块、右键在瞄准面上放置方块，挖除/放置后相邻面立即正确渲染、无洞穿/缺面/z-fighting，不要求性能指标，只要求主观流畅。多人联机、背包/合成/生物/昼夜循环/无限流式加载/存档读档/精美贴图美术均不在本次范围内。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 进入并观察一个真实的体素世界 (Priority: P1)

玩家打开关卡后，发现自己站在一个由方块组成的、地势有起伏（不是纯平地）的小世界中，可以用第一人称视角自由转向观察四周，并能看清至少两三种不同类型的方块分层出现（例如地表、浅层、深层各不相同）。

**Why this priority**: 这是验证"体素世界是否存在、是否看起来像一个真实的方块世界"的最基础前提。如果这一步不成立，后续的挖掘/放置都没有意义。这是整个 feature 里唯一一个"即使单独实现也能证明核心引擎机制可行"的最小子集。

**Independent Test**: 在编辑器中按下 Play，无需任何挖掘/放置操作，仅靠观察世界的外观（地形起伏 + 多种方块分层）即可判定通过。

**Acceptance Scenarios**:

1. **Given** 关卡已在 PIE 模式下加载完成，**When** 玩家观察周围地形，**Then** 能看到明显的高低起伏（而非一块完全平坦的地面）。
2. **Given** 世界已生成完成，**When** 玩家从地表向下方或侧面观察任意一处地形剖面，**Then** 能看到至少两种及以上视觉上可区分的方块类型按深度分层出现。
3. **Given** 玩家处于世界中任意位置，**When** 玩家操作视角转动，**Then** 视角跟随操作实时转动，没有明显卡顿或撕裂。

---

### User Story 2 - 行走探索世界 (Priority: P1)

玩家可以用标准的第一人称移动输入（前后左右移动 + 视角转动），在世界中自由行走探索，移动会被世界中的方块正确阻挡（不会穿模/掉出世界）。

**Why this priority**: 没有移动能力，玩家只能站在原地看，无法"探索"，也无法走到想要挖掘/放置的位置。这是让 User Story 1 的世界变得"可进入"的必要能力，和 User Story 1 共同构成"可玩"的最低门槛，因此同为 P1。

**Independent Test**: 在已生成的世界中，仅测试移动与碰撞（不涉及挖掘/放置），验证玩家可以走到世界的不同角落而不穿透地形或坠落出世界边界。

**Acceptance Scenarios**:

1. **Given** 玩家站在世界中的地面上，**When** 玩家输入前进/后退/左右移动，**Then** 玩家位置相应移动，并且不会穿透固体方块。
2. **Given** 玩家走到一处地形高低变化处（例如小山丘边缘），**When** 玩家继续朝该方向移动，**Then** 玩家作为受重力影响的角色会被地形正确阻挡（无法穿墙），遇到可行走高度差时能够正常上坡/过渡，不会出现穿模或卡死在方块内部的情况。

---

### User Story 3 - 挖除瞄准的方块 (Priority: P2)

玩家将视角瞄准世界中的任意一个方块，按下鼠标左键后，该方块被移除；移除后原本被该方块遮挡的相邻方块面立即正确显示出来，不出现洞穿、缺面或 z-fighting 等渲染错误。

**Why this priority**: 这是"编辑世界"能力的第一半，是体素沙盒区别于普通静态场景的核心机制之一。依赖 User Story 1/2 已经成立（有世界、能走到目标附近瞄准）。

**Independent Test**: 在已能行走的世界中，对准任意暴露的方块左键点击，观察该方块是否消失、相邻面是否正确重新渐变显示，不涉及放置功能即可独立验证。

**Acceptance Scenarios**:

1. **Given** 玩家视角瞄准一个可见的方块，**When** 玩家按下鼠标左键，**Then** 该方块从世界中消失，原方块所在位置变为空洞。
2. **Given** 一个方块被挖除且周围存在相邻方块，**When** 挖除动作完成，**Then** 相邻方块朝向空洞的那一面立即正确渲染可见，没有缺面、洞穿到异常内部空间或 z-fighting 闪烁。
3. **Given** 玩家视角没有瞄准任何方块（例如瞄准天空或超出世界边界），**When** 玩家按下鼠标左键，**Then** 不发生任何方块移除（无操作，无报错）。

---

### User Story 4 - 在瞄准面上放置方块 (Priority: P2)

玩家将视角瞄准世界中任意一个已存在方块的某个外露面，按下鼠标右键后，会在该面的外侧新增一个方块（使用当前选中的方块类型），新增后与周围方块的渲染同样正确、无渲染错误。

**Why this priority**: 这是"编辑世界"能力的第二半，与挖除共同构成完整的"增删"闭环。放置在逻辑和渲染复杂度上与挖除相近，但依赖"当前选中方块类型"这一额外概念，故单列一个 P2 用户故事，与挖除同等重要但可稍晚于挖除验证。

**Independent Test**: 在已能挖除方块的世界中，对准任意一个暴露面右键点击，观察是否在正确位置生成新方块、且该方块与周围渲染正确衔接，不依赖挖除是否已实现即可独立测试（只要世界里本来就有暴露面）。

**Acceptance Scenarios**:

1. **Given** 玩家视角瞄准一个已存在方块的某个外露面，**When** 玩家按下鼠标右键，**Then** 在该面外侧的相邻格子生成一个新方块。
2. **Given** 新方块已生成，**When** 该方块与周围方块相邻，**Then** 新方块与周围方块的可见面渲染正确，没有缺面、重叠面闪烁（z-fighting）或洞穿等问题。
3. **Given** 放置目标位置会与玩家自身所在的空间重叠，**When** 玩家尝试在该位置放置方块，**Then** 系统拒绝该次放置（不允许把玩家卡在方块里面）。

---

### Edge Cases

- 玩家瞄准世界边界之外（没有任何方块、纯空气）时按下左键或右键：不应发生任何方块增删，也不应报错或崩溃。
- 玩家对着世界最底层（设计上的"地基/基岩"层，见 Assumptions）尝试挖除：该层方块被设计为不可挖除，用于防止玩家挖穿世界底部掉入虚空；点击该层应无效果（无操作）。
- 玩家在两个区块(chunk)的交界处挖除或放置方块：交界两侧的区块都必须各自正确地重新计算并显示自己朝向交界面的可见面，不能出现其中一侧区块没有同步更新的情况。
- 连续快速多次点击左键/右键（例如连续挖除一整条隧道）：每次操作都应正确生效，不应出现因上一次重建尚未完成而丢失、误判或崩溃的情况。
- 玩家瞄准的方块恰好是世界生成时就已经不存在的"空气"格子（例如山丘之间的凹陷处）：左键点击应视为"未瞄准到方块"，不发生任何移除。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在玩家进入关卡时生成一个由多个区块(chunk)拼接组成的有限大小世界，世界整体地势必须通过噪声函数呈现起伏变化，而非完全平坦。
- **FR-002**: 系统必须在生成的世界中按照深度呈现至少三种视觉上可区分的方块类型（地表层、中间层、深层），使玩家能够直观分辨不同方块类型的分布。
- **FR-003**: 系统必须为世界的最底部提供一层不可被挖除的方块（地基/基岩层），防止玩家将世界挖穿导致掉出世界边界或看到世界"底部之外"的空虚空间。
- **FR-004**: 玩家必须能够使用标准第一人称输入（视角转动 + 前后左右移动）在世界中自由移动和观察，移动过程中必须被世界中的固体方块正确阻挡（不能穿模）。
- **FR-005**: 系统必须支持玩家通过瞄准（视线方向的射线检测）确定自己当前"看向"的是哪一个方块（如果有）。
- **FR-006**: 玩家必须能够对当前瞄准的方块执行"挖除"操作（鼠标左键），执行后该方块必须从世界数据和视觉呈现中移除。
- **FR-007**: 玩家必须能够对当前瞄准的、已存在方块的外露面执行"放置"操作（鼠标右键），执行后必须在该面外侧新增一个方块，方块类型为玩家当前选中的类型。
- **FR-008**: 系统必须在任意一次挖除或放置操作完成后，立即正确更新受影响区域（包括跨越区块边界的相邻区块）的可见表面渲染，不能出现洞穿、缺失面或 z-fighting。
- **FR-009**: 系统必须阻止玩家在会与玩家自身碰撞体发生重叠的位置放置方块。
- **FR-010**: 系统必须阻止玩家瞄准世界之外（空气/无方块/超出世界边界）时发生任何方块增删效果。
- **FR-011**: 挖除/放置操作触发的世界重建，必须在玩家主观感受上是"即时"的——不能出现肉眼可察觉的卡顿、掉帧或界面冻结。
- **FR-012**: 玩家必须能够通过按键循环切换当前选中的方块类型（用于放置），不需要图形化的热键条/背包 UI——每次按下切换键，当前选中类型按固定顺序前进到下一种可用类型。
- **FR-013**: 世界的区块(chunk)数据组织方式必须允许未来按玩家周围范围动态加载/卸载区块（即使本 MVP 阶段是一次性生成所有区块），不能是一种事后无法扩展为按需加载的硬编码结构。
- **FR-014**: 玩家角色必须是受重力影响、具有碰撞体的标准第一人称角色控制器（不能穿墙、不能无碰撞悬浮飞行），移动和观察方式与常见第一人称/角色扮演游戏的标准操作一致。

### Key Entities *(include if feature involves data)*

- **Voxel World（体素世界）**: 代表整个可探索的游戏空间，由多个 Chunk 拼接而成，具有整体的世界边界（水平和垂直范围）。
- **Chunk（区块）**: 世界的基本组织单元，内部包含一个三维的方块网格数据；每个 Chunk 知道自己在世界中的位置，并负责根据自身及相邻 Chunk 的方块数据生成可见表面。
- **Block / Voxel（方块）**: 世界中最小的可操作单元，具有"类型"（例如地表层/中间层/深层/基岩）属性，决定其外观和是否可被挖除。
- **Player（玩家）**: 代表当前控制视角与移动的用户，是一个受重力影响、具有碰撞体的第一人称角色，具有位置、朝向，以及通过按键循环切换的"当前选中的方块类型"（用于放置）这一状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家进入关卡后，无需任何额外操作即可直接看到一个具有明显地势起伏、且能分辨出至少三种不同方块类型分层的世界。
- **SC-002**: 玩家能够在不穿模、不卡死、不掉出世界的前提下，自由行走到世界内的任意可达位置。
- **SC-003**: 对世界中任意一个可见方块执行挖除操作后，相邻方块的可见面在同一帧或下一帧内即正确更新，玩家在正常游玩节奏下感知不到渲染错误（洞穿/缺面/z-fighting）。
- **SC-004**: 对世界中任意一个可见方块外露面执行放置操作后，新方块与周围环境的渲染同样在一帧左右内正确衔接，无可感知的渲染错误。
- **SC-005**: 连续执行至少 20 次挖除/放置混合操作（例如挖一条短隧道再部分填回），系统全程不出现卡顿感知、崩溃或世界数据损坏（如方块位置错乱）。
- **SC-006**: 一名此前没有看过本项目代码的人，仅通过实际游玩（不看源码），就能直观感受到"这是一个可以挖掘和建造的方块世界"，而不需要额外解释才能理解在做什么。

## Assumptions

- 本 MVP 阶段世界范围是一次性生成的有限大小世界（足够玩家行走探索几分钟的规模），不要求真正的"无限世界"或按距离动态流式加载/卸载——那是后续 feature 的主题；但数据结构本身（按 Chunk 组织）不能是事后无法扩展为按需加载的方式（见 FR-013）。
- 本 MVP 阶段无需实现任何存档/读档机制；世界状态（包括玩家的挖掘/放置修改）只需要在当前这一次 Play 会话内保持正确即可，编辑器重新运行可以重新生成一个全新世界。
- 方块的视觉区分可以仅通过简单的纯色或基础材质实现，不需要像素贴图美术资源或贴图集（Texture Atlas）。
- 世界地形使用确定性噪声生成（例如固定种子），使得每次演示/测试时地形是可复现的，而不是每次运行都完全随机、不可预期。
- 单机单人场景，不考虑任何网络同步或多名玩家共享同一世界的情况。
- 本 MVP 不包含物品栏/背包 UI、资源拾取与计数、合成/制作系统、生物/AI、昼夜循环与天气系统——这些均为后续 feature 的范围。
- 挖除/放置的最大可操作距离（玩家与目标方块之间的最远瞄准距离）采用该类第一人称交互的常规合理范围，不要求达到某个精确量化的米数指标；具体数值将在 `/speckit-plan` 阶段结合实现细节确定。
